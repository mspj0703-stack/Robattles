# RoBattles! Alpha 1.0 — 첫 플레이 UX / 캐릭터 선택 화면 명세

- 문서 ID: `RB-UX-01`
- 작성: 2026-10-26 (KST)
- 기준: `RoBattles_PROJECT_MASTER_S5_R1_2026-10-25.md`
- 성격: **S5-R1 범위 내 UI/UX 세부 설계안**. 새 게임 규칙·스킬 수치를 추가하거나 변경하지 않는다.
- 구현 상태: **기획 정리 / 코드 반영·Studio 검증 미확인**
- 담당: GPT Work UI. 실제 서버 상태 연결과 충돌 파일 통합은 개발 관리·검수방.

## 1. 설계 목표

첫 접속자가 **어디를 눌러야 하는지**, **캐릭터가 어떻게 다른지**, **현재 경기가 왜 시작되지 않는지**, **죽은 뒤 어떻게 돌아오는지**를 별도 긴 튜토리얼 없이 파악하도록 한다.

품질 가정: 설명 읽기보다 게임에 들어가는 행동이 우선. 첫 선택까지 기본 동작 2회(`PLAY`→캐릭터 선택·출전). 강제 튜토리얼, 자동 캐릭터 선택, 임의 튜토리얼 맵 추가는 하지 않는다.

## 2. 첫 플레이 상태 흐름

1. **미선택 MENU**: 3D 캐릭터가 자동으로 SWORD로 스폰되지 않음. 메인 메뉴에서 `PLAY`→선택 UI.
2. **CHARACTER SELECT**: 5종 카드 모두 노출. 카드 탭 시 상세·조작 설명 갱신, `선택하고 출전` 버튼으로 서버에 선택 제출. 서버 승인 전에는 출전 완료로 표시하지 않음.
3. **WAITING**: 승인 후 BRICKYARD 진입. 조작 가능, 스킬 연습 가능, **PvP 피해·KO·데스·궁극기 충전 불가**. `참가자 n/2명 · 다른 플레이어 기다리는 중` 상태 표시. 실제 참여 인원은 서버 participantCount 이용.
4. **COUNTDOWN**: 참가자 2명 이상이면 서버 기준 5초 카운트다운. 대기와 실제 전투 전환 시 피해 허용 상태를 서버 기준으로 전환. 카운트다운이 취소되면 다시 WAITING 표현.
5. **ACTIVE**: 상단에 남은 7분 경기 시간, 서버 제공 순위·KO·참가자 수. 서버 적중 확정일 때만 히트마커/피해 숫자.
6. **DEAD**: 게임 화면 대신 사망 오버레이, 서버 기준 4초 부활 시간 표시. 캐릭터 변경은 **다음 부활부터**; 저장된 현재 선택을 함부로 지우지 않음. 실제 공격·움직임 불가 상태는 서버가 확정.
7. **RESPAWN**: 서버 보호 2초를 가볍게 표시하고 첫 승인 공격 시 보호 해제. 시각 안내가 피해 규칙을 결정하지 않음.
8. **RESULTS**: 정상 종료에서만 12초 결과 화면. 퇴장자 제외·연결 중인 참가자 기준 서버 재계산 rank 사용; 공동 순위 그대로 표시. 이후 같은 서버 다음 경기 준비.
9. **CANCELLED**: 참가 인원 1명 이하 20초 유예 만료 시 즉시 WAITING으로 전환. `인원 부족으로 경기가 취소됐어요` 안내를 잠깐 표시. **승자/정상 결과/12초 지연 없음**.
10. **REJOIN**: 동일 matchId 재접속·출전은 서버가 기존 KO·데스를 복원. UI는 서버에서 온 해당 상태 그대로 사용. 이전 화면 캐시/새 플레이어 간주로 0을 임의 설정하지 않음.

## 3. 메인 메뉴 정보 구조

- 큰 행동 버튼 `PLAY` (최우선)
- 보조 진입 `CHARACTERS`(정보 열람), `HOW TO PLAY`(한 화면 조작 도움말), `SETTINGS`
- 게임명과 BRICKYARD 배경은 유지하되 PLAY 집중도를 방해하는 장식 최소화.
- `HOW TO PLAY`: `WASD 이동 · Ctrl 달리기 · Space 점프 · Shift 회피 · LMB 기본 공격 · RMB 보조 공격 · 1/2/3 스킬 · F 궁극기 · V 카메라 · Tab 순위표`; `R 재장전(지원 캐릭터)` 별도 표기.
- 첫 방문 자동 팝업/스킵 강제 튜토리얼은 넣지 않음.

## 4. 캐릭터 선택 화면

### 배치(PC 16:9 우선)

- 왼쪽: SWORD / PAINTBALL / SUPERBALL / TIMEBOMB / SLINGSHOT **5개 카드가 한눈에 보이게**. 카드에서 역할과 체력을 빠르게 비교.
- 가운데: 임시 R6 캐릭터 모델 프리뷰(없으면 정적 실루엣으로 폴백). 불필요한 실시간 고성능 3D 렌더 중복 금지.
- 오른쪽: 캐릭터 이름, 한 줄 역할 소개, HP, 기본/보조 공격과 1·2·3·F, 패시브의 짧은 설명. 수치·쿨타임은 최신 서버 데이터/공식 기획에 있는 값만 표시.
- 하단 또는 우측 큰 CTA `선택하고 출전`. 서버 선택 승인·스폰 완료 전 중복 입력 방지와 대기 표시.
- 캐릭터를 탐색하는 행위와 실제 선택·출전 요청을 분리. 선택 카드 클릭만으로 스폰하지 않음.
- 카드의 `쉬움/보통/어려움`은 **조작 복잡도에 대한 UX 안내**이며 승률·성능 평가가 아님. 실제 플레이테스트 후 수정 가능.

### 카드 문구(UX 초안)

| 캐릭터 | 난이도 초안 | 한 줄 소개 | 처음 선택하는 사람에게 설명할 핵심 |
|---|---|---|---|
| SWORD | 보통 | **검으로 파고들어 연속 공격하는 근접 파이터** | 접근·패링·연계 공격 |
| PAINTBALL | 쉬움 | **빠른 페인트 사격으로 계속 압박하는 슈터** | 연사·탄약·재장전 |
| SUPERBALL | 어려움 | **튕기는 공과 회수 공격으로 공간을 장악** | 반사 궤적·공 회수 |
| TIMEBOMB | 보통 | **폭탄을 설치하고 타이밍에 맞춰 터뜨리는 전술가** | 설치·원격 기폭·범위 조절 |
| SLINGSHOT | 어려움 | **충전과 탄도 조준으로 정밀하게 맞히는 사수** | 충전·탄도·정밀 적중 |

※ TIMEBOMB은 설치·기폭 두 단계 입력 때문에 실전 조작이 복잡할 수 있어 `보통`은 시험 전 임시 제안. 테스트에서 어렵게 느껴지면 `어려움`으로 변경.

### 각 상세 스킬 표기 예

- LMB/RMB/1/2/3/F 위치를 공통으로 고정해 캐릭터를 바꿔도 버튼을 찾기 쉽도록.
- 미구현 기능을 사용 가능한 것처럼 소개하지 않음.
- 핵심 설명은 각 스킬당 1줄. 상세 수치가 너무 많으면 간결화하되, 서버와 다른 수치 만들어 쓰지 않음.
- 툴팁 입력 예시: `RMB · 패링` / `1 · 연속 베기` / `F · 궁극기`; 실제 스킬명은 `Characters.luau`와 맞출 것.

## 5. HUD와 상황별 짧은 안내 문구

| 상태 | 추천 문구 | 주의 |
|---|---|---|
| MENU | `PLAY` | 캐릭터 미선택 자동 스폰 금지 |
| SELECT | `캐릭터를 골라 전투에 참가하세요` | 카드 클릭만으로 출전 금지 |
| WAITING(1명) | `참가자 1/2명 · 다른 플레이어를 기다리는 중` | 참가 인원 서버 기준 |
| WAITING 연습 | `대기 중에는 피해가 적용되지 않습니다` | KO·게이지 획득 없음 |
| COUNTDOWN | `경기 시작까지 5 · 4 · 3 · 2 · 1` | 실제 남은 시간 서버 기준 |
| ACTIVE | `남은 시간 / 내 순위 / KO / 참가자` | rank 직접 계산 금지 |
| DEAD | `부활까지 4초 · 캐릭터 변경 가능` | 변경 다음 부활부터 적용 |
| PROTECTED | `부활 보호 중` | 실제 해제 서버 기준 |
| LOW_POPULATION | `참가 인원 부족 · 경기 취소까지 남은 시간` | 20초 서버 기준 |
| CANCELLED | `인원 부족으로 경기가 취소됐어요` | 정상 RESULTS 렌더링 금지 |
| RESULTS | `경기 결과` | 12초, 서버 순위·동률 보존 |

### HUD 시각 우선순위

1. 조준점, 체력, 스킬 사용 가능/쿨타임, 궁극기 게이지
2. 남은 경기 시간, KO, 순위, 참가자 수
3. 명중 마커·피해 숫자·킬피드
4. 비전투 안내는 눈에 띄되 화면 중앙을 오래 가리지 않음

## 6. PC / 태블릿 뷰

- **PC 16:9 기준**에서 메뉴·5카드·스킬 안내가 동시에 식별 가능한지 확인.
- 작은 화면·태블릿은 콘텐츠가 화면 밖으로 사라지지 않게 패널을 세로로 재배열하거나 상세 영역을 스크롤 가능하게 함.
- 모바일 터치 전투 조작의 정식 지원을 이 명세로 추가하지 않음.
- 키보드 단축키가 제한되는 환경에서 조작 도움말은 표시할 수 있으나 신규 입력 계약 추가 금지.

## 7. 테스트 / 수용 조건

**기능 P0**
- MENU에서 캐릭터 선택 전 캐릭터 자동 스폰 없음.
- 캐릭터 승인 후 WAITING 진입; 서버 참가 수 표시.
- 대기 연습에서 피해·KO·데스·궁극기 획득 없음.
- COUNTDOWN/ACTIVE/DEAD/RESULTS/CANCELLED 상태가 섞이지 않음.
- 죽은 중 캐릭터 변경 후 다음 부활 반영.
- KO/데스/순위와 결과 행은 서버 데이터만 소비. 퇴장자 결과에서 제외, 공동 순위 보존.
- 경기 취소 즉시 WAITING. 12초 정상 결과 화면으로 지연되지 않음.

**사용성 P1**
- 5개 카드 모두 보이고 고유 역할 소개가 한눈에 읽힘.
- HP/궁극기/스킬 버튼은 서로 겹치지 않음.
- 처음 접속한 플레이어가 PLAY→선택→출전 경로를 쉽게 찾음.
- 16:9 및 축소 창에서 텍스트 잘림·클릭 불가 요소 없음.
- 임시 R6 프리뷰가 없어도 출전 자체가 막히지 않음.

## 8. 구현·협업 경계

- UI 담당: 카드, 문구, 화면, 아이콘, 서버 상태 소비, 접근성·반응형 배치.
- 전투 담당: 실제 캐릭터·피해·스킬·입력 승인, 서버 유효 적중.
- Match 담당: 참가/대기/카운트다운/경기/리스폰/취소/재접속 및 서버 순위.
- 통합 담당: `Main.client`, Remote/Feedback 구독·입력 중복·UI와 Match 계약 연결. 파일 전체 덮어쓰기 금지.
- Roblox Studio 실기 확인 전에는 완료/릴리스 승인 표시 금지.

## 9. 동기화 메모

이 문서는 공통 S5-R1 마스터의 **UX 보충 명세**다. 마스터의 확정 규칙을 덮어쓰지 않는다. 다른 채팅에 공유한 후 통합 개발방이 `docs/`에 추가 및 체크리스트 상태를 관리해야 한다. 실제 다른 채팅/저장소로 자동 동기화되지는 않는다.

향후 S5-R1과 이 문서 사이에 충돌이 발견되면 **S5-R1 마스터 우선**. 게임 규칙 변경이 필요하다면 기획방에서 새 버전으로 별도 확정한다.
